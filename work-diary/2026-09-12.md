## Architecture questions

Not implementation steps — decisions to make on paper before the grey-box plan can go `active`.
Each is cheap to settle now and expensive to discover halfway through the renderer. Ordered by how
much downstream work each one blocks. As each is settled it graduates into `docs/architecture.md`
or the plan; the diary just records that it was open.

### ~~The time model — what the slider actually does~~ CLOSED

**The time slider was cut later the same day.** All four questions here were about what a
continuous scrub implies for the schema, so three evaporate and the fourth resolves cheaply:

- ~~Decide whether an edit carries a date.~~ **No.** Edits carry no date, and their order means
  nothing temporally — it exists for undo, not for time.
- ~~Choose crossfade or incremental apply.~~ **Neither.** Discrete states are rendered whole.
  Whether switching hard-cuts or gets a short transition is a presentation choice with no schema
  consequence, so it waits until there is something on screen to judge.
- ~~Decide what an `add` looks like mid-scrub.~~ **There is no mid-scrub.**
- ~~Resolve merging against the `remove` op.~~ **Pre-merge once per state.** This tension only
  existed because a scrub could demand any partial combination of edits applied to a merged mesh.
  With a small fixed set of states, each state's geometry merges ahead of time and swaps whole.

Worth recording: the cut removed more machinery than it removed feature. The sharpest architectural
tension in the design went with it, and it went for free.

### The document's references

- [ ] **Decide what happens when a re-import drops an edit's target.** Edits reference
      `osm/way/12345`, but upstream OSM splits, merges and deletes ways. A November re-import that
      orphans a `remove` should warn loudly rather than fail silently. The alternative is
      snapshotting the footprint into the edit so it survives the target disappearing.
- [ ] **Decide how hotspots attach.** Currently a flat list with positions. A hotspot about a 2045
      intervention should follow that object when the editor moves it, and should not be visible in
      2026. Attach by object id, keep free positions, or allow both — and settle whether a hotspot
      belongs to the scene or to a scenario.
- [ ] **Decide whether scenarios compose.** Independent edit lists over the same baseline is
      simplest; a shared "common 2045" substrate avoids duplicating the edits that every future
      agrees on. The roadmap's test is that a second scenario is nearly free — check both shapes
      against it.

### Constraints with dates attached

- [ ] **Resolve the workshop write path — this one has a hard date.** `docs/roadmap.md` argues the
      editor should be usable by the NFL workshops on 26–27 Sep, so participants place their own
      interventions and the exhibition accumulates over its run. `CLAUDE.md` non-goals say the
      editor is localhost-only and clipboard-only, with no auth, uploads or database. Both cannot
      hold. Either workshop output is collected as JSON and hand-merged overnight — which fits the
      non-goals — or a minimal write path gets pulled forward, which breaks them. Decide now;
      discovering it on the 26th is the bad outcome.
- [ ] **Fix the axis and unit convention once, and write it down.** Footprints are planar `[x, y]`
      and three.js is Y-up. lat/lon → local metres → scene coordinates needs one canonical mapping,
      unit-tested, before anything is extruded. `CLAUDE.md` already names projection and transform
      normalization as pure functions to test — this is that decision, made explicit.
- [ ] **Check the Thai typography budget.** The schema is bilingual `{en, th}` throughout and the
      audience is largely Thai. A Thai webfont subset is real weight against a sub-5 MB budget, and
      Thai line-breaking in the DOM panels wants verifying on a phone before the content lands.

## Notes

**Decisions locked today** (all now written up in `CLAUDE.md`, which is the source of truth — this
is just the trail):

- Next.js App Router + TypeScript on Vercel, React Three Fiber + drei for the 3D. Godot and Unity
  considered and rejected: wasm payload size, flaky iOS Safari, and the content is text panels over
  a 3D scene, which is DOM's job.
- **The scene is a document; edits are a diff over an immutable OSM baseline; the editor is the
  viewer plus a layer.** The failure mode to watch for is ever building a second renderer.
- September non-goals, written down so they stay decided: no terrain, no free-roam avatar, no auth
  / uploads / database.
- **Three licences, not one.** Code MIT, OSM-derived `baseline` ODbL, authored 2045 content
  CC BY-SA 4.0. A blanket MIT would have misstated the terms the moment generated OSM data landed
  in the repo, because ODbL is share-alike and cannot be relicensed. The root `LICENSE` stays pure
  MIT so GitHub's detector still reads it; the split lives in the README table.
- **Assets go in the repo, not Git LFS.** LFS complicates Vercel builds, is metered on public
  repos, and would undermine the offline static export the exhibition machine depends on. The perf
  budget is the size discipline instead — anything too big for git was already too big for a phone.
  Authoring sources (`.blend`, `.fbx`, `.psd`) are ignored; optimised `.glb` is committed.
- **The OSM cache is ignored; the generated scene document is committed.** Same reasoning as
  `docs/architecture.md`: the exhibition must not depend on Overpass being up.

**Carried into tomorrow:** roadmap item 1 — schema plus grey-box blockout, now written up as
[`2026-09-12_scene-schema-greybox.plan.md`](../plans/2026-09-12_scene-schema-greybox.plan.md) and
still `draft`. Orthographic camera, click-to-select, panel opens, no art. The discipline note in
`docs/roadmap.md` applies: if the grey-box version is not interesting to click around on day one,
art will not rescue it. Find that out tomorrow, not on day five.

**But not straight into code.** The Architecture questions above came out of rereading
`docs/architecture.md` against itself. Cutting the time slider closed the whole first group, which
leaves six open — of which one is still load-bearing on the schema: what happens to an edit whose
OSM target disappears on re-import. The schema is the one thing `docs/roadmap.md` says must be
right on day one, because everything authored depends on it. Settle that on paper first; the
blockout is still a one-day job afterwards.

**Two cuts, in order: the time slider, then the present.** Neither wanted as a feature. The viewer
now shows 2045 futures only — two or three of them as states of one toggle, with no scrub and no
"today" state a visitor can reach. Removed from `docs/roadmap.md` item 3, the interaction model in
`docs/architecture.md`, the `CLAUDE.md` non-goals list, the plan's out-of-scope list, and the
one-line descriptions in `CLAUDE.md` and the README.

The document model survives untouched. Edits stay a diff over an immutable baseline, because that
rule was always about re-import safety, cheap extra scenarios and free undo rather than about the
slider. **`baseline` is now a substrate rather than a view** — still essential, since it is what
makes 2045 Wat Ket recognisably Wat Ket, but never rendered on its own outside development.

Two consequences worth carrying forward, both written into the docs rather than left here:

- **The hotspot copy now has to do work it did not have to do before.** The present was the
  reference point that made an intervention legible as a *change*; without it, a visitor who does
  not know Wat Ket sees a plausible neighbourhood and cannot tell what was done to it. Each hotspot
  has to carry its own before-and-after. That is a content requirement, and it raises the stakes on
  roadmap item 5 rather than lowering them.
- **Two scenarios is now a hard minimum, not a nice-to-have.** With one, the toggle is dead and the
  methodological argument — several arguable futures rather than one prediction — collapses into a
  single prediction. If only one scenario is ready by 24 Sep that is a schedule emergency, and it
  is better to know that now than on the 23rd.

**Convention now standardised across repos.** Filenames moved to hyphenated dates
(`2026-09-12_slug.plan.md`, `2026-09-12.md`) to match `nadiio`, which has 112 plans and 22 diary
entries on that convention. The plan above predates the four conditional gates and is marked
`draft` until they are filled in — that is the gate working, not an oversight.
