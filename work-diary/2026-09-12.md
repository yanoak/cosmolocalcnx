## Architecture questions

Raised by rereading `docs/architecture.md` against itself, then worked through interactively the
same evening. **All closed.** Each decision now lives in the architecture doc, the roadmap or
`CLAUDE.md`; this is just the record that it was once open and how it went.

### ~~The time model~~ CLOSED by cutting the time slider

- ~~Does an edit carry a date?~~ **No.** Order exists for undo and means nothing temporally.
- ~~Crossfade or incremental apply?~~ **Neither.** Discrete states render whole.
- ~~What does an `add` look like mid-scrub?~~ **There is no mid-scrub.**
- ~~Merging versus the `remove` op?~~ **Pre-merge once per state.** The sharpest tension in the
  design went with the slider, and it went for free.

### ~~The document's references~~ CLOSED

- ~~What happens when a re-import drops an edit's target?~~ **Snapshot and warn.** Every `remove`
  and `replace` stores `wasAt`, the target's centroid at authoring time, so a `replace` survives
  its target disappearing upstream. The import warns loudly and lists orphans rather than failing
  — it has to keep working at 2am in week two.
- ~~How do hotspots attach?~~ **`target` where an object exists, `at` where it does not.** One or
  the other. Moving an object in the editor carries its hotspot along; a hotspot about the
  riverbank or a junction gets a bare position. **Scope is two-level** — shared hotspots at scene
  level, intervention hotspots inside their scenario.
- ~~Do scenarios compose?~~ **No.** Each is an independent edit list over the same baseline. A
  shared 2045 layer would say something true and save some duplication, but it buys a composition
  order and a second place to look when something renders wrong, at a scale this project will not
  reach. Revisit at a fourth scenario.

### ~~Constraints with dates attached~~ CLOSED

- ~~The workshop write path.~~ **Collected and merged overnight, not written live.** Participants
  export scene JSON from the localhost editor; it is merged and redeployed that evening. Every
  September non-goal survives, the exhibition still accumulates on a one-day lag, and there is an
  editorial step between a stranger's placement and the public scene. The alternative was a save
  endpoint in the week of opening, which breaks three non-goals and adds auth, storage and
  moderation at the worst moment.
- ~~Fix the axis and unit convention.~~ **Metres, three.js native — Y up, X east, −Z north.**
  Footprints are planar `[x, y]` mapping to scene `[x, −y]`. Assets are baked to this at ingest,
  never rotated at runtime. Written into `docs/architecture.md` under "Coordinates and units",
  which was the whole point of the question.
- ~~The Thai typography budget.~~ Not an architecture question after all — it is a task, now
  scoped into roadmap item 5: subsetted webfont, line-breaking checked on a real phone.
- ~~Measure on a cheap Android.~~ Now the closing step of roadmap item 1 and the last task in the
  grey-box plan. **Device will be borrowed at the residency** — worth asking in the first days
  rather than on the 23rd, since it is the only task in that plan that cannot be done at a desk.

## Notes

**Decisions locked today** (all now written up in `CLAUDE.md`, which is the source of truth — this
is just the trail):

- Next.js App Router + TypeScript on Vercel, React Three Fiber + drei for the 3D. Godot and Unity
  considered and rejected: wasm payload size, flaky iOS Safari, and the content is text panels over
  a 3D scene, which is DOM's job.
- **The scene is a document; edits are a diff over an immutable OSM baseline; the editor is the
  viewer plus a layer.** The failure mode to watch for is ever building a second renderer.
- September non-goals, written down so they stay decided: no terrain, no free-roam avatar, no auth
  / uploads / database.
- **Three licences, not one.** Code MIT, OSM-derived `baseline` ODbL, authored 2045 content
  CC BY-SA 4.0. A blanket MIT would have misstated the terms the moment generated OSM data landed
  in the repo, because ODbL is share-alike and cannot be relicensed. The root `LICENSE` stays pure
  MIT so GitHub's detector still reads it; the split lives in the README table.
- **Assets go in the repo, not Git LFS.** LFS complicates Vercel builds, is metered on public
  repos, and would undermine the offline static export the exhibition machine depends on. The perf
  budget is the size discipline instead — anything too big for git was already too big for a phone.
  Authoring sources (`.blend`, `.fbx`, `.psd`) are ignored; optimised `.glb` is committed.
- **The OSM cache is ignored; the generated scene document is committed.** Same reasoning as
  `docs/architecture.md`: the exhibition must not depend on Overpass being up.
